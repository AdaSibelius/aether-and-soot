## 1. Mandatory Pre-Flight Protocol (Execute Before Writing Code)

### Rule 1.1: The Anti-Duplication Search Rule
Before creating any new type, helper function, component, or system, you **MUST** inspect [ARCHITECTURE.md](./ARCHITECTURE.md) and [docs/architecture-map.md](./docs/architecture-map.md), and search the existing codebase (`grep` / file view) to verify it does not already exist:
- **Spatial & Grid Lookups**: Do NOT write custom coordinate math or entity loops. Use `isWithinBounds`, `getTileCell`, `setTileCell`, `findEntitiesAtPoint`, and `findBlockingEntityAtPoint` from `src/sim/spatial/grid.ts`, or `findPortalAtPoint` from `src/sim/spatial/portals.ts`.
- **Line-of-Sight & Pathfinding**: Use `computeVisibleTiles` / `isPointVisible` from `src/sim/spatial/fov.ts` and `hasWalkablePath` from `src/sim/spatial/generator.ts`.
- **Randomness**: Do NOT create new PRNG classes or call non-deterministic browser PRNGs. Use the `SeededRNG` instance hydrated in `src/sim/core/engine.ts` (`rng.nextInt(min, max)`, `rng.nextFloat()`, `rng.nextUint32()`).
- **Schemas & IDs**: Reuse branded schemas (`EntityIdSchema`, `BlueprintIdSchema`, `StratumIdSchema`, `LimbSlotIdSchema`, `FactionIdSchema`, `CommodityIdSchema`) from `src/schemas/primitives.schema.ts`.

### Rule 1.2: The Pre-Flight Impact Analysis Block
Before modifying any file or creating a new feature, you **MUST** output a concise **Impact Analysis Checklist** in your response covering these 6 points:
1. **Schemas Impacted (`src/schemas/`)**: Which Zod schemas (`components`, `commands`, `events`, `blueprint`, `primitives`) require new fields or union variants?
2. **Serialization & Save-State Impact (`WorldStateSchema`)**: Does this change alter `WorldState` structure in `src/sim/core/world.ts`, and will `serializeWorld` / `deserializeWorld` remain 100% compatible?
3. **Existing Infrastructure Reused**: Which exact functions from `src/sim/spatial/` or `src/sim/systems/` will be called instead of writing new utility code?
4. **File Size & Modularity Check**: List the current line counts (`wc -l`) of every file you plan to touch. If any target file will exceed **250 lines** (or is already near the **300-line hard fail limit**), state the name of the new sub-module you will extract.
5. **Client / HUD Impact (`src/client/`)**: Does `projectWorldToVisualFrame` or `formatEventMessage` in `src/client/ui/EventFormatter.ts (via npm run hermes:chronicler)` need to handle new visual flags or `SimEvent` variants?
6. **`STATE.md` Prescription & Roadmap Reconciliation (Sanity Check & Grooming Protocol)**: Before integrating any P1/P2/P3 prescriptions generated by the local Hermes LLM in `STATE.md` into the active phase, you MUST execute the following strict Sanity Check and Grooming process:
   - **Sanity Check (Antigravity vs. Local Hermes)**: As the Antigravity executive agent, you are the final arbiter of codebase integrity. Before integrating any P1/P2/P3 prescriptions generated by the local Hermes LLM in `STATE.md` into the active phase, you MUST evaluate them for architectural validity.
   - **Filter (The Boundary Rule)**: Local models can hallucinate. Discard any Hermes suggestions that violate ECS separation, attempt to inject simulation logic into `src/client/`, or attempt to wire game telemetry/mechanics into tooling scripts (e.g., modifying `tests/scripts/` for gameplay features).
   - **Evaluate**: If mechanically sound and aligned with core design pillars (e.g., deep physical/social simulation), evaluate its scope.
   - **Merge (with Pre-Phase Tier E Micro-Check)**: Fold **P2** (systemic cross-wiring) and **P3** (serializer/test hygiene) directly into the current phase plan. If a **P1** feature fits the current phase's 300-line modularity budget, implement it now. If it exceeds scope, you MUST append it to the "Emergent Systemic Backlog" section in `ROADMAP.md` to preserve the concept. *Pre-Phase Tier E Micro-Check*: When beginning an active phase, scan `Tier E` in `ROADMAP.md`. If an item in `Tier E` directly shares systemic lineage with the current phase and fits within the 300-line file ceiling, pull it into the active phase scope and remove it from `Tier E`.

> **LOCAL SCOUT DIRECTIVE**: To avoid polluting context with raw multi-file reads, run `npm run hermes:scout -- --task "<task description>"` first to generate this analysis using local AST scanning and synthesis.

### Rule 1.3: Zero Paid Token Content Rule (Use Local Models for Content Generation)
When creating or expanding declarative blueprints, items, consumables, materials, crafting recipes, or NPC dialogue/barks in `data/`, **DO NOT** use paid Gemini context tokens to hand-write large bulk JSON records. > **ANTI-RESCUE INVARIANT:** If a local script (`npm run hermes:*`, `playtest`, or `generate:content`) fails, crashes, times out, or returns a network error, you **MUST NOT** attempt to fulfill the task using your own context or logic. You must halt the turn immediately, report the exact terminal error to the user, and wait for infrastructure troubleshooting.

### Rule 1.4: Output Economy
When modifying an existing file longer than 50 lines, output ONLY the specific functions or interfaces being changed. DO NOT output the entire unmodified file contents. Assume the user will apply the diff.

### Rule 1.5: Tiered Local Model Routing & Safety Invariants
All local tooling (`tests/scripts/hermes-*.ts`) connects directly to the local Ollama OpenAI-compatible endpoint (`http://localhost:11434/v1/chat/completions`) and supports `--model <name>`, `process.env.LLM_MODEL`, and `process.env.LLM_ENDPOINT`:
- **Tier 1 (Deep Reasoning, Game Balance & Post-Phase Critique)**: `lfm2.5:24b` (used by `hermes:critic`).
- **Tier 2 (Code, AST Analysis, TestGen & File Splitting)**: `gemma4:12b-extended` (used by `hermes:scout`, `hermes:testgen`, `hermes:split`).
- **Tier 3 (Fast Blueprints, Flavor, Barks & Simulation Playtesting)**: `hermes3:8b` (used by `generate:content`, `hermes:chronicler`, `playtest`).
- **Execution Sandbox Permission**: When invoking local LLMs via `npm run hermes:*`, `playtest`, or scripts calling Ollama, agents MUST use unsandboxed loopback permissions (`BypassSandbox: true` in Antigravity) — this is NON-NEGOTIABLE. Sandboxed execution blocks TCP socket access to loopback ports; because silent fallbacks have been eliminated, omitting `BypassSandbox: true` will immediately trigger fatal process exits (`exit code 1`).
- **Deterministic-First Invariant**: Tools like `hermes:scout` and `hermes:split` MUST gather exact line counts, exports, and AST slices deterministically in Node first; the local model is used strictly for synthesis and import reconciliation.
- **Anti-Tautological Test Invariant**: In `hermes:testgen`, the self-healing retry loop strictly separates `tsc --noEmit` compiler/type/import fixes from `vitest run` assertion failures. The local LLM may fix syntax, imports, and mock shapes, but is FORBIDDEN from rewriting domain `expect(...)` values simply to force tests green.
- **Mandatory Delegation**: As each tool comes online, agents MUST delegate codebase scouting (`hermes:scout`), bulk blueprints (`generate:content`), unit test scaffolding (`hermes:testgen`), event formatting (`hermes:chronicler`), and file splitting (`hermes:split`) rather than hand-authoring them in paid context.
- **Flash-to-Reasoning Escalation Trigger**: If an agent turn encounters an `npm run verify` failure (typecheck, boundary check, data validation, or test assertion) that it fails to resolve after **two consecutive attempts**, it MUST halt the turn immediately without making further speculative edits and output:
  `[ESCALATION REQUIRED]: Agent looping on <issue>. Switch to high-tier reasoning agent to diagnose architectural conflict.`

### Rule 2.1: Strict Headless Separation (`src/sim/` vs `src/client/`)
- Files inside `src/sim/` and `src/schemas/` **MUST NEVER** import from `src/client/`, `pixi.js`, `preact`, or reference browser globals (`window`, `document`, `requestAnimationFrame`, `HTMLCanvasElement`).
- `Math.random()` and `Date.now()` are **STRICTLY FORBIDDEN** in `src/sim/` and `src/schemas/` (even inside comments—`npm run check:boundaries` scans raw file text for those tokens).
- `src/client/` **MUST NEVER** mutate `WorldState` directly. All state changes must flow through `dispatchCommand(state, command)`.

### Rule 2.2: Modularity & File Size Ceiling (Hard Gate: 300 Lines)
- Target file length: **<= 250 lines**.
- Hard automated failure ceiling: **300 lines** (enforced by `tests/scripts/check-boundaries.ts`).
- Keep modules single-responsibility: one domain system per file in `src/sim/systems/`, one UI panel per file in `src/client/ui/`.
- **Warning on Near-Cap Files (>= 240 lines)**: `src/client/bootstrap-loop.ts` (271 lines), `src/client/input/keyboard-router.ts` (262 lines), `src/client/input/modal-nav-router.ts` (247 lines), `src/sim/spatial/strata-dungeons.ts` (242 lines), `src/schemas/components.schema.ts` (241 lines), `src/client/renderer/glyph-stage.ts` (240 lines). Do NOT add new functions to these files—extract sub-modules via `npm run hermes:split` before adding new logic.

### Rule 2.3: Zero Untyped Boundaries & Flat Relational ECS
- `any`, `as unknown as`, and `@ts-ignore` / `@ts-expect-error` are **FORBIDDEN**.
- The project compiles with `"strict": true`, `"noUncheckedIndexedAccess": true`, and `"exactOptionalPropertyTypes": true`. Always guard array/record index lookups (`const cell = grid.cells[idx]; if (!cell) return;`).
- **Flat Relational Entities**: Never nest `EntityRecord` objects inside other `EntityRecord` objects. Store all entities in `state.entities[entityId]` and link them via branded `EntityId` strings.
- **Event Sourcing**: Every gameplay state mutation MUST emit a typed `SimEvent` into the turn log so headless tests and the HUD chronicle can inspect the causal chain.

## 3. Mandatory Verification & Git Synchronization Gate (Run Before Completing Every Turn)

You **MUST** run `npm run verify` after any code or documentation modification, confirm **0 errors**, and commit & push all changes before yielding to the user:

```bash
npm run verify
```

This single command executes all four gates in sequence:
1. `npm run typecheck` (`tsc --noEmit`) — Verifies strict TypeScript types and exhaustive `SimEvent` / `GameCommand` switches.
2. `npm run check:boundaries` (`tsx tests/scripts/check-boundaries.ts`) — Verifies zero forbidden imports, zero `Math.random()` / `Date.now()` tokens in `src/sim/`, and enforces the 300-line ceiling across all `.ts`/`.tsx` files.
3. `npm run validate:data` (`tsx tests/scripts/validate-data.ts`) — Validates all JSON files in `data/` against Zod schemas in `src/schemas/blueprint.schema.ts`.
4. `npm run test:sim` (`vitest run`) — Executes the headless deterministic simulation test suite (`tests/sim/*.test.ts`). Every new feature must include at least one deterministic unit test in `tests/sim/`.

### Mandatory End-of-Turn Git Push Protocol
Immediately after `npm run verify` passes with 0 errors, the agent MUST stage, commit, and push all modifications to GitHub before concluding the turn:
```bash
git add -A && git commit -m "<concise descriptive summary>" && git push origin <branch>
```
- **Execution Sandbox Permission for Git**: Modifying `.git/` (`.git/index.lock`) and network transmission to `github.com` require unsandboxed permissions (`BypassSandbox: true` in Antigravity). Always execute git commit and push operations with `BypassSandbox: true`.
- **Zero Dirty Working Tree Invariant**: Ending a turn with unstaged, uncommitted, or unpushed changes (`git status --porcelain` is non-empty, or local commits are ahead of `origin`) is a strict protocol violation. Never ask or wait for the user to commit/push changes you verified.

### Autonomous Branch Retirement & Pruning Protocol
Upon successful completion and verification of any feature, phase, or audit task on a feature branch (`feat/*`, `audit/*`):
1. The agent **MUST NOT** leave stale feature branches lingering locally or on GitHub.
2. Fast-forward merge the verified branch into `main`:
   ```bash
   git checkout main && git merge --ff-only <branch> && git push origin main
   ```
3. Immediately prune the merged branch both locally and remotely:
   ```bash
   git branch -d <branch> && git push origin --delete <branch>
   ```
4. Confirm with `git branch -a` that only `main` remains active and clean.
